# DeFi Labs Navigator

Сайт живёт на **GitHub Pages** (постоянная ссылка), данные подтягиваются из **Google Таблицы** через Google Apps Script. Ничего не нужно запускать с твоего компьютера — всё работает в облаке.

---

## Что куда заливать и настраивать

| Что | Где |
|-----|-----|
| **HTML-сайт** | Репозиторий на GitHub → включаешь GitHub Pages (как обычно). |
| **Данные** | Твоя Google-таблица. Сайт читает её через скрипт в Google Apps Script. |
| **«Мостик»** | Один раз настраиваешь веб-приложение в Google Apps Script — оно отдаёт данные с таблицы в формате JSON для сайта. |

Компьютер после настройки не нужен — и таблица, и скрипт, и сайт работают в интернете.

## Пошаговая настройка (один раз)

### Часть 1. Google Apps Script (отдаёт данные с таблицы)

1. Открой **https://script.google.com** и войди в тот же Google-аккаунт, в котором лежит таблица DeFi Labs Navigator.

2. Нажми **«Новый проект»**. Удали весь код в редакторе (если есть).

3. Открой в своём проекте (в Cursor) файл **`DeFi-Labs-Navigator-AppsScript.js`** из папки `Defi LABS Navigator`. Скопируй **весь** его текст и вставь в редактор на script.google.com.

4. В начале скрипта есть строка:
   ```js
   var SPREADSHEET_ID = '1ZrMaFUyrHmxldFG242OsKHLOWPxhI4H8vCxO-TvL9Zg'; // сайт
   var RWA_POOL_BATTLE_SPREADSHEET_ID = '1NjN5ELRjNVlFSVfJLCQsho32Kod5HRA4JWakZ7KVsJY'; // RWA Jupiter, B6
   ```
   Если твоя таблица та же — ничего не меняй. Если другая — подставь ID своей таблицы (из ссылки: `docs.google.com/spreadsheets/d/**ЭТО_ID**/edit`).

5. Сохрани проект: **Файл → Сохранить** (или Ctrl+S). Название проекта можно оставить любым, например «DeFi Navigator API».

6. Разверни скрипт как веб-приложение:
   - Вверху нажми **«Развёртывание»** → **«Новое развёртывание»**.
   - Рядом с «Выберите тип» нажми шестерёнку и выбери **«Веб-приложение»**.
   - **Описание:** например «API для навигатора».
   - **Выполнять от имени:** **Я** (твой аккаунт).
   - **У кого есть доступ:** **Все** (чтобы сайт на GitHub мог запросить данные).
   - Нажми **«Развернуть»**.

7. В появившемся окне будет **URL веб-приложения** (вид: `https://script.google.com/macros/s/…/exec`). Нажми **«Копировать»** и сохрани эту ссылку — она понадобится в шаге 2.

8. При первом развёртывании Google может попросить **«Проверить приложение»** и разрешить доступ — нажми «Проверить» и разреши доступ своему аккаунту.

---

### Часть 2. Вставить ссылку в HTML

1. В папке проекта открой файл **`defi-lab-navigator.html`** в редакторе.

2. Найди строку:
   ```js
   var DATA_API_URL = '';
   ```

3. Вставь между кавычками скопированную ссылку из шага 1.7. Должно получиться так:
   ```js
   var DATA_API_URL = 'https://script.google.com/macros/s/ТВОЙ_КОД/exec';
   ```

4. Сохрани файл.

---

### Часть 3. Выложить сайт на GitHub Pages

1. Заливай проект на GitHub как обычно (репозиторий, коммит, пуш). В репозитории должен быть файл **`defi-lab-navigator.html`** (можно в корне или в папке).

2. В настройках репозитория: **Settings → Pages**. В разделе **Source** выбери ветку (например `main`) и папку (корень или папку, где лежит HTML). Сохрани.

3. Если главная страница репозитория — корень и там один HTML-файл, часто нужно открывать явную ссылку на него, например:
   `https://ТВОЙ_ЛОГИН.github.io/ИМЯ_РЕПО/defi-lab-navigator.html`  
   (или как у тебя настроен Pages). Эту ссылку можно использовать как постоянную «пиздатую» ссылку на навигатор.

После этого сайт всегда открывается по этой ссылке и подтягивает данные из твоей таблицы. Кнопка **«Обновить»** на сайте перезапрашивает данные из таблицы.

## Структура Google-таблицы (напоминание)

- **Первый лист** — категории. Столбцы: `id`, `name`, `icon`, `description`, `color`.
- **Второй и следующие листы** — инструменты (один лист на категорию, порядок листов = порядок категорий).

В листах с инструментами строка заголовков — первая, где есть и **name** (или название), и **apy** (часто это строка 1; если сверху баннер/пустая строка — может быть строка 2). Колонки, например:  
`name` (или название), `apy` (доходность), `period`, `link` (или url, ссылка), `description` (описание), `pair` (пара), а также по желанию: **`platform`** (платформа / DEX), **`fee`** (уровень комиссии), **`chain`** (сеть / блокчейн).  
Для **period** в JSON подставляется **то же отображение, что в ячейке** (формат из таблицы), поэтому можно задать «7 дней» и т.п. прямо в Excel/Таблице.

Столбец пары: заголовок **`pair`** или **`пара`** (после нормализации). Доходность в шапке может называться также **`apr`**. Других смещений по колонкам нет.

**Локальный сервер (`server.js`)** запрашивает лист диапазоном **`A:ZZ`**, чтобы не обрезать столбцы правее Z (старый `A:Z` мог «съедать» пару).

Проверка логики без таблицы: `node scripts/test-pair-resolution.mjs`

Блок **«Гайды и материалы»** на сайте сейчас скрыт стилем (разметка сохранена); чтобы снова показать — в `defi-lab-navigator.html` убери `display: none` у `.guides-section`.

## Цифры не обновляются / показываются старые (что проверить)

1. **Индикатор в шапке**  
   После успешной загрузки — зелёный бейдж **«Данные обновлены»** с галочкой и временем.  
   **«Офлайн-режим»** или **«Ошибка загрузки»** — данные из скрипта не пришли (см. ниже).

2. **Обновление после правок в таблице**  
   Изменения в Google-таблице подхватываются **после нажатия кнопки «↻ Обновить»** на сайте (или после перезагрузки страницы). Просто сохранить таблицу недостаточно — нужно обновить данные на сайте.

3. **Доступ к веб-приложению**  
   В Apps Script в настройках развёртывания должно быть: **«У кого есть доступ» → «Все»** (или «Все, у кого есть ссылка»). Если стоит «Только я», запрос с GitHub Pages не сможет выполнить скрипт, и данные не подгрузятся.

4. **Та же таблица, что в скрипте**  
   В коде Apps Script в переменной `SPREADSHEET_ID` должен быть ID **той же** таблицы, которую ты правишь. ID виден в ссылке:  
   `docs.google.com/spreadsheets/d/**ЭТО_ID**/edit`.

5. **Структура листов**  
   Первый лист — категории (столбцы: id, name, icon, description, color). Со второго листа — инструменты; в первой строке заголовки, в том числе столбец доходности: **apy**, **доходность** или **доход**.

6. **Консоль браузера (F12)**  
   Открой сайт, нажми F12 → вкладка «Console». При успешной загрузке будет сообщение вроде:  
   `DeFi Navigator: данные загружены из таблицы`.  
   При ошибке или таймауте — предупреждение и тогда показываются резервные (фиксированные) данные.

## Категория RWA — «Битва пуллов RWA» (Solana / Jupiter)

Четвёртая ветка — **RWA**: только **liquidity pool** на Solana (Raydium, Orca и т.д.). **Kamino Lending** и прочий lending не подтягивается.

**Оплата не нужна:** Jupiter Portfolio API работает **бесплатно** (режим без ключа, ~2 с пауза на запрос; раз в час этого достаточно). Платный тариф не требуется. По желанию можно добавить **бесплатный** ключ Free ($0) на [portal.jup.ag](https://portal.jup.ag/) — см. шаг 2 ниже.

### Что сделать тебе (минимум)

| # | Где | Действие |
|---|-----|----------|
| 1 | Google Таблица | Открой лист **«Битва пуллов RWA»**. В **B6** — ссылка `https://jup.ag/portfolio/ТВОЙ_АДРЕС` (как сейчас). Строка **7** — шапка `name / apy / …` (как на ETH). |
| 2 | [script.google.com](https://script.google.com) | Вставь **весь** обновлённый **`DeFi-Labs-Navigator-AppsScript.js`**. **Развёртывание → Управление → Изменить → Новая версия → Развернуть**. |
| 3 | Та же таблица | Меню **DeFi Navigator → Авто-синх RWA каждый час** (один раз). При необходии **Синхронизировать RWA (Jupiter)** вручную. |
| 4 | GitHub | Ничего — пушит агент / ты только смержишь PR при желании. Vercel обновится сам. |

Опционально (если Jupiter иногда отвечает 401): Apps Script → **Project Settings → Script properties** → `JUPITER_API_KEY` = бесплатный ключ с portal.jup.ag (план **Free $0**).

Лист и строку `rwa` в metadata можно создать скриптом с компа:  
`node scripts/setup-rwa-sheet.mjs` (нужен доступ service account к таблице).

Проверка фильтра без API: `npm run test:rwa`

## Локальный сервер (по желанию)

В папке есть **`server.js`** и **`package.json`** — это вариант «с компа» (Node.js). Для облачного варианта они **не нужны**: достаточно GitHub Pages + Apps Script, как описано выше. Если захочешь запускать сайт локально с тем же API — можешь пользоваться инструкциями в комментариях в `server.js` или в старой версии README.
